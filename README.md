# Техническое задание: Demo Web Server

## 1. Введение

Demo Web Server — учебное приложение на Spring Boot для регистрации пользователей и проверки контактных данных. Продукт предназначен для практического тестирования REST-сервисов и поиска логических и runtime-дефектов.

## 2. Основания для разработки

Основанием является задание на практическую работу по созданию исполняемого программного продукта, содержащего 5–8 преднамеренных ошибок. Исходные документы — код проекта и `pom.xml`. Нормативная база: ГОСТ 19.201-78 (ТЗ) и ГОСТ 19.101-77 (виды программных документов).

## 3. Назначение разработки

Программа принимает заявки на регистрацию, проверяет имя, e-mail и телефон, возвращает результат проверки и показывает список принятых заявок. Данные хранятся в памяти и нужны для учебного тестового стенда.

## 4. Требования к программе

### 4.1. Функциональные требования

- `GET /api/users` возвращает список пользователей;
- `POST /api/register` принимает JSON с полями `name`, `email`, `phone`;
- успешная заявка добавляется в список, телефон форматируется как `+7 (XXX XXX-XX-XX)`;
- при ошибках возвращается JSON с сообщением и массивом ошибок.

В учебной версии зафиксированы 7 преднамеренных дефектов: неверная проверка границ имени, непринятые цифры в имени, ошибочная логика e-mail, падение на пустом телефоне, некорректная замена начальной `8`, ошибка форматирования телефона и недостаточная обработка пустых полей.

### 4.2. Надёжность

При корректных запросах сервер сохраняет доступность. Некорректные данные должны возвращать ответ API; исключения фиксируются в журнале Spring Boot. Постоянное хранение и восстановление после перезапуска не требуются.

### 4.3. Условия эксплуатации

Java 17 или новее (рекомендуется Java 21), свободный TCP-порт 8687, не менее 256 МБ ОЗУ. Работа выполняется локально или в локальной сети.

### 4.4. Совместимость

Поддерживаются Windows, Linux и macOS при наличии Java и Maven Wrapper. Обмен выполняется по HTTP/1.1 с JSON UTF-8; клиентом может быть браузер, `curl` или Postman.

## 5. Требования к интерфейсу

Интерфейсом является REST API. Для `POST /api/register` передаются JSON-поля и заголовок `Content-Type: application/json`. Ответ содержит `message`, при успехе — `phone`, при ошибке — `errors`. Графические кнопки и меню не предусмотрены.

## 6. Критерии приёмки

- `./mvnw clean package` завершается без ошибок;
- сервер запускается и отвечает на порту 8687;
- корректная регистрация возвращает успех, а пользователь появляется в `/api/users`;
- негативные запросы возвращают ошибки либо воспроизводят задокументированный дефект;
- не менее 95% согласованных тест-кейсов выполнены с ожидаемым результатом.

## 7. Запуск и тестирование

Из корневой папки проекта:

```bash
./mvnw spring-boot:run       # Linux/macOS
mvnw.cmd spring-boot:run     # Windows
```

Сервер доступен по адресу [http://localhost:8687](http://localhost:8687). Порт задаётся в `src/main/resources/application.properties`.

```bash
curl http://localhost:8687/api/users
curl -X POST http://localhost:8687/api/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Иван","email":"ivan@example.com","phone":"89991234567"}'
```

Сборка и запуск JAR:

```bash
./mvnw clean package
java -jar target/demo-0.0.1-SNAPSHOT.jar
```

## 8. Требования к документации

## 9. Порядок контроля и приёмки

Проверяющая команда собирает проект, запускает сервер и выполняет позитивные и негативные REST-тесты. Для каждого теста фиксируются запрос, входные данные, ожидаемый и фактический ответ, а также наличие дефекта. Приёмка проводится по разделу 6.
